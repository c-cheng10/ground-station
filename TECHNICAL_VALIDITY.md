# Technical validity

The explorer turns NASA’s historical records into a question someone can investigate. A Southern Ontario farm adviser can compare how rainfall and root-zone soil wetness moved in the same month and one month apart. The result describes a regional pattern that a field-level study could investigate further.

| Design choice | Why we made it |
|---|---|
| NASA POWER and the MERRA-2 reanalysis | One API provides annual and monthly values at the same grid locations. MERRA-2 combines observations with a weather model to produce a gridded historical record. The app checks the source, coordinates, units and missing-value flag before using a response. [NASA POWER API](https://power.larc.nasa.gov/docs/services/api/temporal/monthly/) · [NASA MERRA-2](https://gmao.gsfc.nasa.gov/gmao-products/merra-2/) · [Data loader](power-data.js) |
| Six study areas and eight shared variables | The same variables let people compare study areas across the Americas. Temperature, precipitation, humidity, soil wetness, evapotranspiration and wind let them ask how the land and atmosphere change together. [Regions](trend-config.js) · [Variables and units](TRAINING_DATA.md) |
| One regional average from nine grid cells | A 3 × 3 patch gives each point a regional footprint. Cells receive weights proportional to the cosine of their latitude because the east–west width of a degree shrinks toward the poles. Neighbouring cells can share weather, so nine cells produce one regional value per month. Checking how results change with the choice of patch or local ground measurements would test whether they carry over to individual sites. [Data loader](power-data.js) |
| A fixed chart window and monthly baseline | January 1981 through December 2025 gives each study area 45 complete years on the same footing. The anomaly chart compares each month with that calendar month’s 1991–2020 average, so July is compared with July. The correlation calculation removes calendar-month means and a fitted linear trend over the full 1981–2025 window. [Statistics code](trend-statistics.js) |
| Trend size and uncertainty | The app fits a straight line to annual values and reports the slope per decade. Newey–West standard errors allow for related regression errors up to three years apart. Theil–Sen’s median pairwise slope and the Mann–Kendall rank test provide a second check. The classic Mann–Kendall test assumes independent annual values. Holm adjustment accounts for the eight tests made in each region for each method. [Trend code](trend-statistics.js) · [Multiple-test adjustment](trend-explorer.js) · [Newey and West](https://www.nber.org/papers/t0055) |
| Ordered correlations at lags of zero to six months | Pearson’s `r` measures straight-line association from −1 to +1. At a one-month lag, the app pairs each month’s first variable with the second variable one month later. Reversing the variables asks a different question. Claims about causes or future conditions need separate evidence. [Correlation code](trend-statistics.js) |

## Storage and verification

- Supabase keeps one row per grid cell and month, with the eight measurements in columns. The six historical exports contain 29,160 rows. Refresh starts after the latest complete month and saves a new month once NASA supplies all nine cells. A unique key on cell and month makes retries ignore rows already present. In a live recovery test, Refresh restored two archived Southern Ontario rows from September 2026. Both matched the originals across all eight measurements, and the duplicate count was zero. [Database schema](supabase/schema.sql) · [Refresh function](supabase/functions/refresh-climate/index.ts)
- PostgreSQL stores 2,688 precomputed correlations across the six areas, including each ordered variable pair at seven lags. Each row records its method, date range and paired-month count. In Southern Ontario, precipitation and root-zone soil wetness had `r = 0.4959` across 540 same-month pairs and `r = 0.6498` across 539 pairs when soil wetness was measured one month later. The stored window matches the chart window. [Correlation query](supabase/correlations.sql)
- Groq interprets the question and picks the region, ordered pair and lag for a read-only Model Context Protocol (MCP) lookup. The assistant is designed to display the coefficient and sample details from the returned database row. Both server functions are deployed, and the integration passed with a simulated Groq response. Live Groq use requires a configured server API key. [Groq tool documentation](https://console.groq.com/docs/tool-use/remote-mcp)

## AI use

Codex assisted with implementation, testing and documentation. Groq is the model provider for the optional runtime assistant. NASA POWER supplies the climate data, and the repository’s JavaScript and SQL compute the statistics.
